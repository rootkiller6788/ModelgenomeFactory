# `data/zoo/_adversarial/` —— 对抗用例

这个目录不参与 `run`。它存在的唯一目的是：**证明 `canonicalize` 会报错，而不是猜。**

本项目最危险的失败模式不是崩溃，而是**读不懂但假装读懂了** —— 一个宽度对不上的张量
被当成对的读进去，然后报告里出现一个没人会去核对的数字。`canonical.py` 里有一整套
宽度互校，但那些检查只有在**被喂进坏输入**时才真正被验证过。

## 两类用例

**合法但渲染器产不出来**（2 个）

`gpt2.shuffled.json` / `mixtral-8x7b.vllm_shuffled.json`：张量顺序**完全倒序**。
渲染器永远按名字排序，所以这两份清单不可能是它写的。它们必须被接受，而且指纹必须与
同模型的正式清单**逐位相同** —— 这一条盯的是「解析器是不是只认得自己渲染出来的那一种写法」。

**必须报错**（8 个）

每一个都对准一条具体的互校，`cases.json` 里写了**期望的错误信息片段**。
只断言「抛了异常」是不够的：一个 `KeyError` 也能让测试变绿，而它可能来自任何地方。

| 用例 | 对准哪条互校 |
| --- | --- |
| `llama-2-7b.unknown_name` | 名字表：没有任何规则能解释的名字必须报错，绝不能跳过 |
| `llama-2-7b.wrong_role` | **名字匹配上了不等于结构对**：挡住它的是块级结构校验 |
| `llama-2-7b.missing_layer` | 层数对质（少了中间一代会让突变点算到错误的边界上） |
| `llama-2-7b.tie_mismatch` | 权重绑定：config 说没绑，清单说绑了 |
| `llama-3-8b.kv_transposed` | GQA 的 k 投影宽度（转置过的权重「看着像」） |
| `llama-3-8b.qkv_axis` | 融合张量的轴向约定（见下） |
| `mixtral-8x7b.ragged_expert` | 专家参差不齐 —— **真实存在的结构缺陷，而它不会自己报错** |
| `qwen2-7b.no_qkv_bias` | 家族约定是**可证伪的声明**，不是默认值 |

## 已知边界：融合张量的轴向

本项目把融合张量写成**沿最后一维拼接**：vLLM 的 `qkv_proj.weight` 是
`(hidden, (n_heads+2·n_kv)·head_dim)`，即 Llama-3-8B 的 `(4096, 6144)`。

真实 vLLM checkpoint 里是沿第 0 维（`(6144, 4096)`）。所以把真实布局喂进来会**报错**，
`llama-3-8b.qkv_axis` 钉的就是它。

这是「拒绝而不是猜」的正确行为，但它同时是一条**已知的接不上真实 checkpoint 的缝**，
记在 README 附录 B 里。**这条缝不影响任何结论**：融合只是清单的布局属性，
三种方言的指纹逐位相同，参数量与 checkpoint 元数据逐位相同 ——
但下一个人想拿它去读真实权重时，会先撞上这里。

## 运行

```bash
python main.py adversarial          # 跑全部用例
python main.py adversarial --json   # 机读
```

`cases.json` 由 CLI 与 `tests/test_adversarial.py` **共用** ——
于是「命令行说全过的」与「测试说全过的」不可能是两套结论。

这批清单的形状取自真实清单（避免手抄出错），其余手工构造；生成脚本已删除。
要加用例就直接改 `cases.json` + 手写清单。
